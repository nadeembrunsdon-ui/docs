## Remaining checks

Run these in order. Paste each command, its output, its exit code and the date into a new log entry above before you mark a check as passed.

<Steps>
  <Step title="Confirm serial identity after reconnect">
    Unplug the adapter, wait five seconds and plug it back in. Then run:

    ```bash
    date -Is
    lsusb -d 0403:6015
    readlink -f /dev/serial/by-id/usb-www.vgatemall.com_vLinker_FS_D3C6QAZC-if00-port0
    udevadm info -q property -n /dev/ttyUSB0 | grep -E 'ID_VENDOR_ID|ID_MODEL_ID|ID_SERIAL_SHORT'
    ls -l /dev/ttyUSB*
    journalctl -k --since "-5 min" | grep -i ftdi
    ```

    The check passes if the by-id link still resolves to the same `ttyUSB` node that Wine maps, and the serial is still `D3C6QAZC`. If the node changes (for example to `ttyUSB1`), the Wine COM mapping must change too.
  </Step>
  <Step title="Confirm the Wine COM mapping">
    ```bash
    date -Is
    ls -l ~/.wine-pcmhammer/dosdevices/ | grep -i com
    WINEPREFIX=~/.wine-pcmhammer wine reg query 'HKLM\Software\Wine\Ports'
    ```

    The check passes if `com33` points to `/dev/ttyUSB0` (or to the by-id path) and no registry override points it elsewhere.
  </Step>
  <Step title="Confirm the adapter talks ELM327 natively">
    Before you open PCM Hammer, confirm the adapter answers on Linux with the `--self-test` and `--list-ports` options of `vgate_deep_logger.py`, then a short parked session with ignition on:

    ```bash
    python3 ~/Downloads/vgate_deep_logger.py --self-test
    python3 ~/Downloads/vgate_deep_logger.py --list-ports
    python3 ~/Downloads/vgate_deep_logger.py --port /dev/serial/by-id/usb-www.vgatemall.com_vLinker_FS_D3C6QAZC-if00-port0 --no-enhanced --duration 120
    ```

    This isolates adapter problems from Wine problems. Record the session folder name and any errors.
  </Step>
  <Step title="Start PCM Hammer and read PCM properties">
    Close every other program that uses the adapter. Start PCM Hammer from the Wine prefix and capture its output:

    ```bash
    WINEPREFIX=~/.wine-pcmhammer wine "<path to PcmHammer.exe>" 2>&1 | tee ~/pcmhammer-$(date +%Y%m%dT%H%M%S).log
    ```

    With ignition on, use **Read Properties** only. Record the VIN, OS ID, calibration IDs, hardware ID and serial number it reports.

    <Warning>
      Do not use **Read Full Contents**, **Test Write**, **Write Calibration** or **Write Full**. Reading the full flash loads a kernel into PCM RAM and puts the PCM into programming mode. That belongs in BIG-8, not here.
    </Warning>

    The check passes if PCM Hammer reports the OS ID `12205612` (or records a different value with a note) and the log shows no errors.
  </Step>
  <Step title="Log O2 sensor data">
    With the engine at idle, log O2 sensor voltages for at least two minutes, using either PCM Logger or the Python logger:

    ```bash
    python3 ~/Downloads/vgate_deep_logger.py --port /dev/serial/by-id/usb-www.vgatemall.com_vLinker_FS_D3C6QAZC-if00-port0 --no-enhanced --duration 300
    ```

    Record the session folder, the O2 channels returned and a few dated sample values per sensor. The check passes if every expected O2 sensor returns changing values. Note that P0157 (bank 2 sensor 2 low voltage) was stored in earlier logs.
  </Step>
</Steps>

## If PCM Hammer crashes under Wine

The historical crash went through `DevicePicker.AddDiscoveredPorts`, which runs while PCM Hammer enumerates serial ports. These are things to try, not confirmed fixes:

- Remove the duplicate `COM34` mapping so only one COM port points at the adapter.
- Point `COM33` at the stable by-id path instead of `/dev/ttyUSB0`.
- Use a native self-contained Linux build of PCM Hammer instead of Wine. Building one needs the .NET 10 SDK, which is not installed.

Log each attempt, its result and any changes made to the system.
